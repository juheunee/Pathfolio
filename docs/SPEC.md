# Pathfolio 제품 명세

> 기준: [HSU 진로로드맵 개발 공모전](https://app.notion.com/p/411776f72047803db6b1d8821851f90b)의 2026-11-27 통합 문서. 이 문서는 목표 동작이다. 구현 상태와 이번 범위는 [MVP.md](MVP.md)를 본다. 계산 결과는 학교의 공식 학사 판정이 아니다.

## 1. 목적과 용어

Pathfolio는 한성대 신입생·재학생·취업 준비 졸업생이 전공트랙을 탐색하고 교과·비교과 로드맵을 계획·관리하는 PC 웹 프로토타입이다. 관리자는 추천 사례와 학사일정, 집계 데이터를 운영한다.

- **학사 원장:** 확정된 교과 성적·비교과 포인트. 시연에서는 출처를 표시한 가상 데이터이며 학생이 수정할 수 없다.
- **계획:** 로드맵에 배치한 항목. 계획만으로 취득 학점이나 포인트가 늘지 않는다.
- **대표 로드맵:** 계정당 최대 1개. 홈 요약의 기준이며, 진행률·졸업 시뮬레이션은 각 로드맵별로 계산한다.
- **연계/융합:** 1·2트랙이 같은 학부면 연계, 다르면 융합.
- **기준 데이터:** 트랙·교과·개설 학기·이수 요건 등. 출처, 적용 학번/학년도, sample 여부를 함께 관리한다.

기능 ID·우선순위는 [기능명세서 통합본](https://app.notion.com/p/425776f7204780ceacaaf925a4d4fef4), 화면은 [정보구조 통합본](https://app.notion.com/p/425776f72047800392b2f5e2e2db8471), 데이터는 [데이터 설계 통합본](https://app.notion.com/p/425776f72047800bb1c4edbd1e3edea3), 요청·응답 필드는 [API 계약 통합본](https://app.notion.com/p/425776f7204780f7b0d1c81d631ca7cb)을 따른다.

## 2. 주요 사용자 흐름

1. **신입생:** 사전 등록 계정 로그인 → 트랙 둘러보기·조합 비교 → 직접 작성하거나 허용된 선배 로드맵 가져오기 → 학기 계획 저장·대표 설정. 홀랜드 테스트 추천은 P1이다.
2. **재학생:** 로그인 → 대표 계획 요약 → 로드맵별 진행·졸업 시뮬레이션 → 계획 수정 → 공식 이수 결과 대조. 재수강·트랙 변경 시뮬레이션은 P1이다.
3. **취준생:** 로그인 → 졸업 후 5년 마일스톤 작성 → 공개 범위 설정 → 후배가 허용된 계획을 검색·가져오기.
4. **관리자:** 역할 확인 후 집계, 추천 계획, 학사일정을 관리한다(P1).

## 4. 학사·데이터 정책

- 원장은 사용자 단위이며 로드맵에 복제하지 않는다. 계절학기·상상더학기는 종료 뒤 **공식 이수·성적 결과가 원장에 확정된 때**만 취득으로 센다. 종료 날짜만으로 자동 인정하지 않는다.
- 재수강은 C+ 이하만 계획에 다시 놓을 수 있다. 성적 이력은 보존하고 같은 과목 졸업 취득 학점은 한 번만 센다. 예상 성적 시뮬레이션은 원장을 수정하지 않는다. 실제 평점 공식은 자료 대조 전 미확정이다.
- 한 과목의 학점을 두 트랙이나 총 취득학점에 이중 합산하지 않는다. 이미 이수한 과목의 일반 재배치는 막고 재수강만 예외로 둔다.
- Notion 명세는 2026-2 학업이수가이드의 **24학번 이후 융합전공Ⅰ**에 한해 졸업 130학점·비교과 800pt, 트랙당 39학점, 정규학기 통상 18학점·이월 포함 최대 21학점, 비교과 학기당 200pt·8학기차 400pt를 인용한다. 비교과 부족 포인트 가이드는 남은 학기 수와 이 인정 상한 안에서만 제안한다. 다른 학번·제도에 확대 적용하지 않는다. 원문과 적용 범위를 구현 전에 검증한다.
- 교과·요건·개설 학기·비교과 인정 데이터가 없으면 추정하지 않는다. sample 행은 공식 결과와 구분한다. AI가 만든 설명이나 가상 데이터로 공식 판정을 만들지 않는다.

## 5. 추천·트랙 변경 (P1)

RECO-01은 자체 작성 RIASEC 12문항 또는 유형·키워드 직접 선택을 받는다. 동일 입력·규칙 버전이면 동일 조합·근거를 낸다. 1트랙은 입학 단과대학의 허용 트랙에서, 2트랙은 1트랙을 제외한 시연 범위에서 고른다. 결과에는 고용24 검사의 외부 링크를 둔다. 최신 통합본의 추천은 규칙 기반이며 외부 LLM은 필수 흐름이 아니다.

EXPL-04는 3~7학기 학생의 변경 전 전공학점 중 일반선택으로 전환되는 양과 새 트랙 부족량을 보여 준다. 조합 비교나 대표 변경은 기존 로드맵을 삭제하지 않는다.

## 6. 친구 공개·가져오기

FRIENDS는 수락된 친구만, PRIVATE는 작성자만 열람한다. ANONYMOUS는 전체 공개하되 이름·이메일을 숨긴다. PUBLIC은 이름만·이메일만·둘 다 중 선택한다. 이메일 공개 시에만 메일 바로가기를 제공한다. 목록·상세·복사 API 모두 서버에서 권한을 재검사한다. 친구 관계 해제나 비공개 전환 뒤 이전 권한으로 재조회할 수 없어야 한다. 복사본은 기본 비공개이며 원본의 공개 범위를 넓히지 않는다. P0는 시드된 수락 친구 관계로 접근을 검증하고, 친구 요청·수락 UI는 EXTRA-03(P1)에서 제공한다.

## 7. 화면·API 계약

- 목표 업무 API는 /api/v1, JSON은 camelCase, 응답 ID는 문자열이다. 시간은 시간대 포함 ISO 8601, 날짜 전용은 YYYY-MM-DD, 학기는 academicYear와 termCode(1·2·SUMMER·WINTER·SANGSANG)로 구분한다. 인증은 Bearer 토큰. 세부 경로·오류 코드는 위 API 계약 통합본을 따른다.
- 서버는 요청 본문의 accountId·ownerId로 소유자를 정하지 않고 토큰의 사용자로 결정한다. 관리자 역할도 서버에서 검사한다.
- 홈(S-03), 편집(S-10), 결과 반영(S-11), 진행·졸업(S-12), 공개 목록·상세(S-13/14), 교과목(S-16)을 연결한다. 기존 코드의 /api 경로와 PostgreSQL 모델은 목표 계약의 구현 완료를 뜻하지 않는다.

## 8. 비기능 요구와 미확정 사항

- 실제 학생 정보·비밀키를 저장소에 넣지 않는다. 가상 학생·졸업생 50명과 시연 계정은 실제 인물과 분리한다. 로그·오류에 성적 원문·토큰·비밀번호를 남기지 않는다. 관리자 추출은 식별 정보 없는 집계만 제공한다.
- 비밀번호 해시, 서버 권한 검사, 배포 시 HTTPS·CORS·비밀 설정을 확인한다.
- **확정:** 목표 DB는 Oracle이며 PostgreSQL/Prisma 접근 코드는 교체한다. **후보:** node-oracledb·Knex, Vercel·OCI 배포. 연결·계정·비용 검증 전에는 완료로 표시하지 않는다.
- **확인 필요:** Oracle 접속 환경, 학사 가이드 원문·적용 범위, 학점 상한의 경고/차단 경계, 상상더학기 귀속, 재수강 평점 공식, 실제 데이터 사용 권한, 토큰 저장 방식.
