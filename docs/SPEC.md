# Pathfolio 제품 요구사항 명세 (SPEC.md)

- **문서 상태:** v0.1 · 팀 검토용 초안 (2026-11-07)
- **제품:** HSU 진로로드맵 e-Advisor 웹앱 프로토타입 / 서비스명 Pathfolio / 팀 Veylo
- **요구사항 출처:** 사용자 제공 공모전 주제·3개 세션 계획·기술/인증/추천 결정. 세부 정책과 화면은 아래와 같이 **제안** 또는 **결정 대기**로 명시한다.

## 1. 제품 목표

사용자의 학업 데이터를 분석해 맞춤 전공트랙을 제안하고, **학년·학기별 교과·비교과 이수 로드맵을 구성·관리**한다. 전공트랙 변경 시 현재 학업 이력과 향후 이수 요건을 비교한다. 결과는 조언이며 공식 졸업 심사나 전공 배정 판정이 아니다.

## 2. 역할·데이터 가정

- **사용자:** 학생(본인 학업 정보·추천·로드맵을 조회/수정).
- **운영자/관리자:** MVP에 별도 UI를 제공할지는 미정. 시연용 학교/전공 데이터는 검증된 초기 데이터로 등록하는 **제안**.
- **학생 데이터 입력:** 공모전 정보만으로 한성대 학사시스템 자동 연동 권한을 확인할 수 없음. MVP는 사용자가 직접 입력하거나 **허가받은 샘플 데이터**를 사용하는 방식을 기본 제안한다.
- **근거 데이터:** 전공트랙별 필수/선택 이수 요건, 교과목, 비교과 정보는 출처와 기준 학년도 관리 필수. 공식 데이터 미확보 시 시연용 가정임을 표시한다.
- **보안:** 계정별 접근 권한을 서버에서 검사. 개인정보 최소 수집.

## 3. 대표 사용자 시나리오

1. 사용자가 종합정보시스템 학번과 비밀번호로 로그인한다. (회원가입 불가)
2. 학년·학기·이수 과목·학점 및 관심 분야를 등록·수정한다.
3. 전공 추천 요청 시 규칙 기반 계산으로 후보 순위와 근거·추가 확인 사항을 확인한다.
4. AI는 계산된 근거를 바탕으로 이해하기 쉬운 요약을 작성한다. AI 실패 시에도 규칙 기반 결과는 제공된다.
5. 사용자가 관심 전공트랙을 선택해 남은 학기별 교과·비교과 로드맵 초안을 생성한다.
6. 사용자가 계획 항목을 편집하고 저장한 뒤 완료 여부를 관리한다.
7. 전공트랙을 바꾸어 비교하면 필수 요건·현재 이수 내역과의 차이가 표시된다.
8. 재로그인 후 본인 로드맵이 복원된다.

| ROAD-02     | P0       | 로드맵 수정·저장·재조회                       | 재로그인 후 본인 저장 내용 유지                     |
| ROAD-03     | P0       | 활동 완료 여부 관리                           | 예정/진행/완료 등 상태 변경 저장 _(상태명 제안)_    |

| UI-01       | P0       | 핵심 흐름 연결 및 빈 상태/오류 안내           | 학업 정보 부족, 추천 불가, API 오류, AI 실패 처리   |
| DATA-01     | P0       | 규칙/교과·비교과 샘플 데이터 출처와 기준 표시 | 샘플/공식 구분, 기준 연도 확인                      |

**P0은 초안의 MVP 필수 제안**이며 일정·데이터 확보에 따라 팀이 범위를 확정한다. 세부 입력 필드, 학점 계산 방식, 성적 반영 가중치, 전공트랙 목록 등은 제공 자료로 확정할 수 없다.

## 5. 추천 엔진 원칙 (하이브리드)

1. **규칙 엔진이 사실과 계산을 책임진다.** 수강/이수 내역, 학점, 관심 분야, 트랙별 요건 등 검증 가능한 입력으로 비교한다.
2. **설명 가능성:** 점수/순위에 사용된 규칙 버전, 주요 근거, 입력 누락, 미충족 요건을 보여준다.
3. **AI는 설명 보조:** 서버에서 허용된 요약 데이터와 검증된 근거를 전달하여 결과를 사람이 읽기 쉽게 설명하도록 한다. 존재하지 않는 과목·자격 요건·확정 진로를 만들어내지 않도록 별도 검증한다.
4. **AI 장애 시 폴백:** 계산된 후보 목록과 규칙 기반 기본 설명을 제공한다. 사용자의 로드맵 생성 자체를 막지 않는다.
5. **공정성·한계:** 추천 점수는 진로 결정 참고용이며, 실제 전공 선택은 학생이 할 수 있게 한다. 성적/관심도를 자동으로 부정적인 개인 평가로 단정하지 않는다.

**결정 대기:** 추천 점수 산식/가중치, 부족 데이터 정책, 동점 처리, 추천 후보 개수, AI 모델·비용·프롬프트·개인정보 전송 정책.

## 6. 로드맵·트랙 변경 규칙

- 로드맵은 **학생 + 선택 트랙 + 적용 학사기준 + 학기 목록**의 관계로 관리한다(논리적 제안).
- 각 항목은 `교과` 또는 `비교과`로 분류하며 예정 학년/학기, 명칭, 상태, 관련 요건 근거를 연결한다.
- 이미 이수한 과목을 신규 예정 과목으로 중복 배치하지 않도록 검증한다. 단, 재수강 처리와 대체 과목 정책은 학교 규정 확인 후 확정한다.
- 학기별 권장 학점 상한 및 선수과목, 실제 개설 여부는 근거 확보 전 **확정값으로 구현하지 않는다**.
- 트랙 변경 비교는 **공통 충족 요건 / 기존 트랙에만 필요한 요건 / 신규 트랙에 추가로 필요한 요건**을 구분한다.
- 변경 비교만으로 기존 로드맵을 삭제하지 않는다. 새 로드맵 확정 전에 사용자 확인 및 기존 내용 보존 전략을 마련한다.
- 저장 요청 중 중복 클릭, 네트워크 실패, 동시 수정 등을 고려하고 저장 성공 여부를 명확히 표시한다.

## 9. API 경계 (경로 제안, 확정 계약 아님)

| Method                | 경로 예시                  | 목적                                          |
| --------------------- | -------------------------- | --------------------------------------------- |
| POST                  | `/api/auth/register`       | 가입                                          |
| POST                  | `/api/auth/login`          | 로그인                                        |
| POST                  | `/api/auth/logout`         | 로그아웃 _(인증 방식에 따라 달라짐)_          |
| GET/PATCH             | `/api/me/profile`          | 프로필 조회/수정                              |
| GET/POST/PATCH/DELETE | `/api/me/academic-records` | 학업 이력 관리 _(상세 리소스 경로 추후 분리)_ |
| GET                   | `/api/tracks`              | 전공트랙 목록/기준일                          |
| POST                  | `/api/recommendations`     | 추천 계산·설명 생성                           |
| GET/POST              | `/api/me/roadmaps`         | 로드맵 목록·생성                              |
| GET/PATCH             | `/api/me/roadmaps/:id`     | 로드맵 조회/수정                              |
| POST                  | `/api/tracks/compare`      | 트랙 이수 요건 비교                           |

- JSON 요청·응답 규약, HTTP 상태 코드, 표준 `error.code`, 세션/토큰, 페이지네이션, 멱등성, 권한 범위는 FE/BE가 별도 API 계약 문서에서 확정해야 한다.
- 사용자 식별자를 클라이언트가 임의 입력하여 타 계정 데이터에 접근하는 API를 허용하지 않는다.
- 시연용 학교 데이터가 불완전하면 빈 목록/제약을 안전하게 표시하고, 실제 학교 데이터라고 오인되지 않도록 한다.

## 10. 비기능 요구사항·검증

- **보안:** HTTPS 배포(실제 배포 시), 비밀번호 해시, 서버 인증/권한 검사, 비밀정보 환경변수 관리.
- **개인정보:** 실제 학업 데이터 사용 시 수집·보관·삭제 목적과 동의, 외부 AI 전달 범위를 검토한다. 시연은 가상 데이터 우선.
- **정합성:** 같은 학업 이력과 동일 규칙 버전이면 추천 엔진 결과가 재현 가능해야 한다(LLM 설명 문구는 예외).
- **복원성:** AI 호출 실패 시 규칙 결과는 유지. 저장 실패 시 사용자 안내/재시도.
- **접근성·사용성:** 학기 구조·상태·근거를 키보드/스크린리더 사용까지 고려해 표시(구체 기준 추후 확정).
- **성능 목표 수치:** 근거 자료 없으므로 현재 미정. 시연 환경 측정 후 목표 설정.

## 11. 인수 시나리오

- **AT-01:** 회원가입/로그인 후 로그아웃·재로그인 가능, 보호 리소스 비인증 접근 거부.
- **AT-02:** A가 등록한 학업 이력을 B가 조회·수정할 수 없음.
- **AT-03:** 샘플 학업 정보로 추천 후보/규칙 근거/입력 누락을 확인. 동일 조건에서 규칙 결과 재현.
- **AT-04:** AI 호출을 실패시켜도 후보 및 근거가 표시되고 안내 문구가 나옴.
- **AT-05:** 학년·학기별 교과/비교과 로드맵을 생성·수정·완료·저장·재로그인 후 조회.
- **AT-06:** 트랙 A/B를 비교하여 공통/추가 이수 필요 요건을 표시하고 기존 계획을 의도치 않게 삭제하지 않음.
- **AT-07:** 데이터 없음·유효하지 않은 학점·서버 실패의 오류 화면/재시도 검증.

## 12. 미결정 사항과 변경 관리

- 과목·비교과·트랙 공식 데이터의 출처/사용 허가, 학사기준 연도.
- 로그인 정책 및 DB/ORM, API 상세, 개인정보 파기 정책.
- 추천 알고리즘의 가중치, 점수 표시 여부, AI 호출 비용/제한.
- 학기별 학점 제약, 선수과목·전공트랙 변경 정책.
- 담당자와 데모 일정·배포 방식.

위 항목은 이 문서만으로 임의 확정하지 않는다. 변경 시 요구사항 ID와 `MVP.md` 인수 기준, 관련 API·데이터 계약, 테스트를 함께 갱신한다.
