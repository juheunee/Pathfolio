# Pathfolio MVP 범위와 완료 기준

> 2026-11-28 기준. [SPEC.md](SPEC.md)의 목표 기능 중 이번 시연 범위를 정한다. 우선순위는 [Notion 기능명세서 통합본 v3](https://app.notion.com/p/425776f7204780ceacaaf925a4d4fef4)을 따른다. 목표와 현재 구현은 구분한다.

## 1. 검증할 경험

학생이 사전 등록 계정으로 로그인해 **본인에게 허용된 학업 결과를 확인하고**, 트랙 조합을 탐색한 뒤 학기 계획·졸업 후 5년 계획을 작성·저장한다. 로드맵별 진행·졸업 가능성을 확인하고 다른 학생의 허용된 계획을 가져와 수정할 수 있어야 한다. 데이터는 재로그인 뒤 남고 타 계정에는 권한대로만 보인다. 신입생·재학생·취준생 메인이 각기 맞는 시작점을 제공한다.

학생의 교과 성적·비교과 포인트 직접 입력은 범위 밖이다. 시연에는 출처를 구분한 가상 학사 원장을 사용하고 학생은 교외활동·학사제도 결과와 계획 완료만 입력한다. 최신 통합본에서 홀랜드 추천은 P1이다.

## 3. P1: P0 통합 뒤 진행

- RECO-01: 자체 RIASEC 12문항 또는 유형·키워드 직접 선택으로 재현 가능한 1·2트랙 조합과 근거를 보인다. 자료 부족 시 탐색 화면으로 이동한다.
- RECO-02, ROAD-04, SHARE-04: sample 기반 유사 강의·마일스톤·인기 직무 추천. 표본 수와 sample 표시가 필요하다.
- RESULT-03, EXPL-04: 재수강 평점 및 3~7학기 트랙 변경 시뮬레이션. 원장과 기존 계획을 수정하지 않는다.
- PROG-03/04: 일정·회고. COMM-01/02: 조합 라운지·신고. EXTRA-03: 친구·시간표.
- ADMIN-01/03/04: 집계 추출, 추천 계획·학사일정 관리. 관리자 역할은 서버에서 확인한다.

## 4. 시연·인수 시나리오

1. **AT-01:** 신입생·재학생·취준생·관리자 계정으로 로그인한다. 각 홈이 맞고 로그아웃 뒤 보호 API가 거부된다.
2. **AT-02:** 학생 A의 원장·비공개 계획은 B가 조회·변경할 수 없다. 수락된 친구는 FRIENDS 계획만 보고 PRIVATE 전환 뒤 접근이 끊긴다.
3. **AT-03:** 신입생은 트랙을 둘러보고 두 조합을 비교해 계획을 만든다. 재학생은 가상 원장을 확인하고 교과·비교과 계획 및 교외활동 결과를 입력한다. 교과 성적·비교과 포인트 수정은 거부된다.
4. **AT-04:** 미개설 학기·중복 과목 배치는 차단된다. C+ 이하 재수강 예외와 학점 경고가 보인다. 계획 학점은 취득에 더하지 않는다.
5. **AT-05:** 학기 카드·5년 카드·대표 설정을 저장하고 재로그인해 조회한다. 로드맵별 진행·졸업 화면은 취득과 계획을 구분한다.
6. **AT-06:** 허용된 선배 계획을 전체·카드 단위로 가져온다. 내 복사본 수정은 원본에 영향이 없고 성공만 집계된다. 같은 요청 재전송과 실패는 제외된다.
7. **AT-07:** 빈 원장, 지원하지 않는 학번·트랙, 서버·DB 오류에 이유와 다음 행동이 보인다. sample 출처와 공식 판정 아님 안내가 보인다.

P1 추천을 시연할 때는 로그인 → 학업 결과 확인 → RIASEC 또는 직접 선택 → 규칙 근거 확인 → 조합으로 로드맵 생성 → 편집·저장 → 재조회로 연결한다. 외부 AI 설명은 필수 조건이 아니다. 선택적으로 도입했다가 실패하면 규칙 결과·근거와 기본 안내를 유지하며 계획 작성은 계속 가능해야 한다.

## 5. 범위 밖과 현재 상태

학교 시스템 실시간 연동, 학생의 공식 원장 직접 수정, 공식 졸업 심사, 자유 대화형 AI 상담, 모든 학번·트랙 완전 지원, 모바일 앱은 제외한다. 학교 접근 권한·검증 자료·운영 정책 또는 별도 개발 범위가 필요하기 때문이다. PDF 추출·교수 검색·해시태그·챗봇은 P2다.

현재 main에는 React 4개 화면(/, /academic, /courses, /roadmap), PostgreSQL/Prisma 서버, API와 sample 응답이 있다. 화면의 초안은 브라우저 메모리에 있고 새로고침하면 사라진다. 이번 문서 작업에서 DB 실행·배포·인수 테스트를 검증하지 않았으므로 **완료 항목은 없다.** Oracle 연결, 화면/API 통합, 위 사례의 실행 결과가 확인된 뒤 상태를 갱신한다.
